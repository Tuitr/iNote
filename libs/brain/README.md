# libs/brain — Brain на LLM (зона B)

Brain из J2 (`libs/contracts/src/contracts/agent_side.py`): получает от агента `TurnInput` и `ToolExecutor`,
возвращает `TurnResult`. Работает в процессе агента, включается `AGENT_BRAIN=llm`. Сам не видит `user_id`,
не ходит в Redis и MCP: инструменты вызывает только через `ToolExecutor`, `caller` подставляет агент.
Подтверждение пользователю агент строит из `actions[].result.data`, а не из текста модели.

## Как устроено

| Модуль | Что делает |
| --- | --- |
| `llm.py` | `LlmClient` — один вызов модели с инструментами; `FakeLlmClient` — ответы по сценарию для тестов |
| `gigachat.py` | `GigaChatClient` — REST GigaChat без SDK: OAuth-токен, function calling, повтор, запасная модель |
| `prompt.py` | системный промпт, `PROMPT_VERSION`, блок времени (сейчас, недели, таблица 14 дней) |
| `llm_brain.py` | `LlmBrain.run` — цикл модели с инструментами и защиты; `resume` — кнопка уточнения без модели |
| `factory.py` | `openLlmBrain(settings)` — Brain с клиентом по `LLM_PROVIDER` на время жизни агента |
| `settings.py` | `LlmSettings`, переменные `LLM_*` |
| `eval/` | eval: кейсы, сверка, отчёт и трассы (`python -m brain.eval`) |

**Ход (`run`).** Модель получает системный промпт с блоком времени и фокусом (короткий id, вид, название,
время), историю (до 10 реплик) и фразу. Инструменты — из `tools.listTools()` плюс виртуальная `ask_user`.
Цикл до `LLM_MAX_STEPS` вызовов модели: вызов инструмента → его `summary` обратно модели → снова модель.
После `list_items` модель второй раз не зовётся: агент рисует список из data.

Итог решает код, а не текст модели:

- `done` — был успешный изменяющий вызов;
- `answer` — только чтение (список, поиск) или ответ текстом;
- `clarify` — модель вызвала `ask_user` или встреча пересеклась (`status: conflict`, варианты — `free_slots`);
- `error` — код LLM (`llm_timeout`, `llm_rate_limited`, `llm_bad_output`, `llm_no_action`) или инструмента.

**Защиты.** Одинаковый вызов второй раз не выполняется. id записи — только из фокуса или результатов этого
хода, иначе модель получает подсказку искать через `search_items`. Время без смещения в MCP не уходит.
На неизвестный id, время без смещения, `validation_error` и `past_time` модель исправляется один раз,
второй раз — ход заканчивается ошибкой. «Записал» без изменяющего вызова — `llm_no_action`.

**Уточнения (`pending`).** Формат свой, агент его не разбирает:

- `{"kind": "call", "tool", "args", "choices": [{поле: значение}, …]}` — кнопка выполняет вызов без модели
  (вопрос о времени из `ask_user`, свободное окно при конфликте);
- `{"kind": "ask", "question"}` — свободный вопрос: подпись кнопки уходит модели обычным ходом.

Варианты `ask_user` проходят те же защиты, что и вызов модели; не прошли — вопрос остаётся свободным.

## Промпт и `PROMPT_VERSION`

Текст — `SYSTEM_PROMPT` в `prompt.py`, правила толкования времени — из плана B («утром» — 09:00, «в 10»
после 10:00 — завтра, встреча без времени — вопрос, длительность не названа — `ends_at` не передаётся и т. д.).
Промпт лежит под снапшотом (`tests/unit/__snapshots__/test_prompt.ambr`): любая правка видна в ревью, и вместе
с ней меняется `PROMPT_VERSION`. Версия пишется в лог каждого хода (`brain_turn`) и в отчёт eval.

Описания инструментов и полей, по которым модель выбирает вызов, — в коде D: `TOOL_DESCRIPTIONS`
в `services/mcp/server.py` и `Field(description=…)` в `libs/contracts/tools.py`.

## Переменные

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `LLM_PROVIDER` | `fake` | `fake` — модель без сети и ответов (агент стартует, ход — `llm_bad_output`); `gigachat` — GigaChat |
| `LLM_MODEL` | `GigaChat-2-Max` | основная модель |
| `LLM_FALLBACK_MODEL` | `GigaChat-2-Pro` | запасная, если основная не ответила после повтора; пусто — без неё |
| `LLM_TIMEOUT_S` | `20` | таймаут одного вызова, не больше 20 (ход агента — 40 с) |
| `LLM_MAX_STEPS` | `4` | сколько раз за ход можно вызвать модель |
| `LLM_GIGACHAT_CREDENTIALS` | — | ключ авторизации (Base64 из личного кабинета), обязателен для `gigachat` |
| `LLM_GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | `_PERS` — физлица, `_B2B` и `_CORP` — юрлица |
| `LLM_GIGACHAT_CA_BUNDLE` | — | путь к сертификату НУЦ Минцифры; пусто — системные сертификаты |
| `LLM_GIGACHAT_AUTH_URL`, `LLM_GIGACHAT_API_URL` | адреса Сбера | OAuth и API |

На стенде профиль выбирает Brain (`Makefile`): `mock` — `AGENT_BRAIN=scripted`, `LLM_PROVIDER=fake` (бесплатно,
e2e); `full` — `AGENT_BRAIN=llm`, `LLM_PROVIDER=gigachat`.

## Как включить GigaChat

1. Получить ключ авторизации в личном кабинете GigaChat API и вписать в `.env`: `LLM_GIGACHAT_CREDENTIALS=…`,
   при необходимости `LLM_GIGACHAT_SCOPE`.
2. Сертификат: API GigaChat подписан НУЦ Минцифры, которого нет в системных сертификатах. Скачать корневой
   сертификат с gosuslugi.ru, положить рядом с проектом, смонтировать в контейнер агента и указать путь
   в `LLM_GIGACHAT_CA_BUNDLE`.
3. `make up PROFILE=full`. Без ключа агент не стартует — ошибка видна в `make logs SERVICE=agent`.
4. Первый eval: `make eval` (платно).

## Eval

- `make eval-fake` — оракул: фейковая модель отвечает ровно ожидаемыми вызовами. Бесплатно, проверяет раннер
  и кейсы, должен давать 100 %.
- `make eval` — GigaChat, три повтора, ключ из `.env`. Платно: только по прямой просьбе владельца B.
  Свои параметры: `uv run python -m brain.eval run --provider gigachat --model GigaChat-2-Pro --repeat 3`.
- `uv run pytest -m eval tests/eval` — тот же прогон с порогом «обязательные сценарии ≥ 90 %»; без ключа
  пропускается, в CI денег не тратит.

Кейсы — `tests/eval/cases.yaml` (формат и правила сверки — в `eval/cases.py`). Отчёт (`report-*.json`: точность
всего, по группам и по обязательным сценариям, задержка p50/p95, токены, проваленные кейсы) и трассы
(`traces-*.jsonl`: вызовы, итог и причины провала по каждому прогону) — в `.eval/`.

## Тесты

`uv run pytest libs/brain` — без сети и денег: GigaChat на фейковом транспорте (respx), `LlmBrain` на
`FakeLlmClient` и фейковом `ToolExecutor`, блок времени на замороженных моментах, раннер eval на оракуле.

## Известные слабые места

- Не проверено на настоящем GigaChat: принимает ли он `temperature=0`, как часто отвечает текстом вместо
  вызова, насколько точно считает даты. Первый `make eval` покажет.
- GigaChat за ответ вызывает одну функцию: фраза с двумя действиями («создай две задачи») — два шага модели,
  при `LLM_MAX_STEPS=4` до конца может не дойти.
- «Записал» без вызова ловится списком слов — перефразировка его обойдёт (агент дополнительно не даёт `done`
  без успешного изменения).
- Ответ на свободный вопрос текстом (а не кнопкой) модель понимает по истории; аргументы прошлого хода
  ей не передаются.
- Пересечение при переносе (`update_item`) уточняется вариантами, но кнопки «Всё равно» у агента для него нет —
  она есть только для `create_event`.
