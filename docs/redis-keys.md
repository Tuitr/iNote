# Реестр ключей Redis (J7)

Владелец — **C**. Новый ключ появляется только через PR сюда с ревью C (CODEOWNERS).
Ключ без строки в этой таблице в код не попадает; в тесте — проверка TTL.

## Правила

- Формат: `va:v1:<сервис>:<сущность>:<id>`. `<сервис>` и `<сущность>` — `[a-z][a-z0-9_]*`,
  `<id>` — `[A-Za-z0-9_.-]+`, **без `:`** (иначе ключ не разобрать). Строит ключи `common.redis.RedisKey`.
- **TTL у каждого ключа.** Единственное исключение — `va:v1:mcp:ver:{user_id}` (белый список
  `common.redis.NO_TTL_WHITELIST`); `KeyedRedis` откажется писать без TTL любой другой ключ.
- В Redis только то, что можно потерять: источник правды — PostgreSQL (правило 4 CLAUDE.md).
- Политика вытеснения — `volatile-lru`, `maxmemory` 256 МБ на стенде (`deploy/docker-compose.yml`):
  вытесняются только ключи с TTL, поэтому версии данных без TTL не пропадут, а кеш — может.
- `INCR va:v1:mcp:ver:{user_id}` — только после коммита в PG (правило 5).

## Как добавить ключ

1. Строка в таблицу выше: ключ, кто пишет и читает, TTL, зачем.
2. В коде — только через `RedisKey(service, entity, id)` и `KeyedRedis` с `ttlS`.
3. Integration-тест на настоящем Redis проверяет формат и TTL (пример — `services/bot/tests/integration/test_redis_adapters.py`).
