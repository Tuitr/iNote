- 2026-10-21 — camelCase в Python-коде (функции, методы, переменные, атрибуты), snake_case на проводах (JSON, ключи Redis, переменные окружения, пути); мост — `WireModel` в `libs/common` с `alias_generator=to_snake`; в ruff отключены N802, N803, N806, N815, N816. Почему: единый стиль кода зоны C, провода по стандарту не меняются. Статус: **предложено C, утвердить на G0** (касается `libs/common`, которой пользуются все).
- 2026-10-21 — менеджер пакетов uv: виртуальный workspace в корне, `uv.lock` один на репо, `uv run` во всех командах. Почему: нативные workspaces (у poetry их нет), один lock для всех сервисов, быстрый `uv sync` в Docker, команды в CLAUDE.md уже на `uv run`. Статус: **предложено C, утвердить на G0** (открытое решение «uv или poetry»).
- 2026-10-21 — настройки ruff, mypy, pytest, coverage и import-linter — в корневом `pyproject.toml` (блок зоны C), а не в каждом пакете. Почему: команды из CLAUDE.md запускаются из корня; mypy и pytest не читают настройки вложенных пакетов, и без корневых `strict` и `asyncio_mode` теряются. Статус: принято в ветке C, на G0 — общее для всех зон.
- 2026-10-21 — качество кода: pre-commit (pre-commit-hooks, gitleaks, ruff, mypy, import-linter, проверка `uv.lock`, формат сообщения коммита `type(scope): текст`), те же проверки в CI (`.github/workflows/ci.yml`). Почему: одинаковые проверки локально и в CI, секреты не попадают в git. Статус: **предложено C, утвердить на G0**.
- 2026-10-21 — дедуп апдейтов MAX: в схеме MAX (max-messenger/api-schema 0.0.33) у апдейта нет `update_id`, поэтому бот строит его сам — blake2b от естественного ключа: `mid` сообщения, `callback_id` + время нажатия, `chat_id` + время старта (`msg-…`, `cb-…`, `start-…`). Ключ Redis прежний: `va:v1:bot:upd:{update_id}`, TTL 24 ч. Почему: стабильный id для повторной доставки, без выдуманных полей MAX. Статус: принято C.
- 2026-10-21 — marker long polling хранится в Redis (`va:v1:bot:marker:poll`, TTL 24 ч — не дольше дедупа, тогда повтор после рестарта отсекается дедупом) — только для реального MAX; у фейкового MAX очередь в памяти, его marker тоже в памяти. Почему: при падении процесса полученная, но не обработанная страница не теряется. Статус: принято C.
- 2026-10-21 — «Слишком часто» отправляется один раз за окно лимита (когда счётчик стал ровно «лимит + 1»), на нажатие кнопки отвечаем всегда. Почему: не спамить пользователя и не тратить лимит MAX 30 rps; без ответа на callback клиент MAX крутит индикатор. Статус: принято C.
- 2026-10-21 — бот обрабатывает только личные диалоги с людьми (`chat_type = dialog`, `is_bot = false`); группы, каналы и боты игнорируются с записью в лог. Почему: ассистент персональный. Статус: принято C.
- 2026-10-21 — у голосового в схеме MAX только `url` и `token`, длительности и mime нет: лимит длины голосового (G2) проверяет ASR по байтам, а не бот по метаданным. Формат — тоже по байтам (`OggS`), как и было. Статус: принято C, **сообщить A**.
- 2026-10-21 — базовый адрес Bot API MAX — `platform-api2.max.ru` (dev.max.ru/docs-api), токен — только в заголовке `Authorization`. Почему: так в актуальной документации; в CLAUDE.md исправлено. Статус: факт из документации.
- 2026-10-21 — стенд S0: `deploy/docker-compose.yml`, профили `mock` и `full` (пока совпадают), один общий `deploy/docker/python.Dockerfile` (uv sync строго по `uv.lock`, без dev, пакеты не editable, пользователь `app`, uvicorn — PID 1), заглушки чужих сервисов — одна картинка `deploy/stub` (stdlib, владелец в `STUB_OWNER`). Наружу опубликован только бот на `127.0.0.1:8001` — ради `/dev/max/*`; `/internal/*` под токеном и на стенде наружу не выходит (Caddy, S1). Версии образов закреплены: `python:3.12-slim`, `ghcr.io/astral-sh/uv:0.12.24`, `redis:7.4-alpine`, `pgvector/pgvector:pg16`. Почему: одна команда `make up`, одинаковые образы у всех. Статус: принято C, compose согласовать с D.
- 2026-10-21 — J4: таймаут вызова Scheduler → бот 10 с; `delivered=false` в ответе не бывает — недоставка выражается кодом ошибки (`chat_not_found` 404 — без повторов; 429/5xx/таймаут — повтор); `attempt` 1…5. Почему: Scheduler решает по статусу и коду, без разбора тела. Статус: **предложено C, согласовать с D на G1**.
- 2026-10-21 — J2: атрибуты моделей в Python — camelCase (как весь код C, см. строку выше), JSON-примеры — snake_case; `TurnInput.now` обязан быть в поясе `tz` (проверка в модели); в `TurnInput` нет `user_id`. `TurnResult`, `Clarify`, `Brain` — набросок, формат решает B. Статус: **предложено C, согласовать с B на G1**.
- 2026-10-21 — реестр Redis: предложено переименовать `va:v1:asr:{sha256}` → `va:v1:asr:cache:{sha256}` (нет сущности) и `va:v1:api:list:{user_id}:{ver}:{hash}` → `…:{user_id}.{ver}.{hash}` (`:` в id ломает разбор). Статус: **предложено C, подтвердить A и D**.
- 2026-10-21 — J2: `TurnResult.error_code` дополнен кодами ошибок инструментов (`validation_error`, `not_found`, `past_time`, `conflict`, `rate_limited`, `internal`, `upstream_*`) — ход, закончившийся ошибкой инструмента, приходит как `outcome=error` с кодом инструмента; незнакомый код сводится к `internal`. Прежние значения `llm_*` не тронуты. Почему: renderer выбирает текст ошибки по коду. Статус: **добавление C в набросок B, согласовать с B на G1**.
- 2026-10-21 — `ScriptedBrain` (C): `list_items` получает период `[from, to)` — полночь начала и полночь после конца в поясе пользователя, неделя с понедельника; «напомни» без времени не создаёт запись, а просит время (уточнения — S2); `create_task` для напоминания шлёт `due_at` и `remind_at` одним моментом. Статус: принято C; границы `to` (включительно или нет) — вопрос к D.
- 2026-10-21 — J3, клиент MCP: официальный SDK `mcp` 2.x (`mcp>=2.3,<3`; в 2.x нет `mcp.server.fastmcp`, клиент — `mcp.Client` поверх Streamable HTTP, транспорт `httpx2`). Одна сессия на процесс, её держит фоновая задача в `TaskRegistry` (группа задач SDK должна жить в одной задаче); обрыв → переподключение с паузой 0,2…5 с. Ключ идемпотентности `<trace_id>:<n>` получает **каждый** вызов хода, поэтому таймаут (5 с) и обрыв повторяются один раз с тем же ключом; протокольная ошибка MCP и `isError` не повторяются. `isError` без конверта `error` → код `internal` с текстом сервера; `listTools` при недоступном MCP → пустой список. Статус: принято C; где лежит конверт при `isError` — вопрос к D.
- 2026-10-21 — временная MCP-заглушка C (`deploy/stub/mcp`) вместо заглушки D до мержа: те же формы ответов, что в плане. Статус: временно, удалить после мержа.
