# max_app — мини-приложение MAX (зона E)

Календарь в MAX: показывает то, что ассистент сохранил по голосу или тексту. Данные — только чтение
через API зоны D (J5, `/v1`), экран при открытии выбирается по `start_param` от бота (J6).

Стек: React 19, TypeScript, Vite 6, [MAX UI](https://github.com/max-messenger/max-ui) (`@maxhub/max-ui`),
MSW для моков, Vitest + Testing Library для тестов. React 19, а не 18 из плана: MAX UI 0.8 требует 19.

## Запуск

```bash
npm install
npm run dev:mock   # без бэкенда: ответы /v1 отдаёт MSW из src/mocks
npm run dev        # с настоящим api на localhost:8000 (прокси Vite, см. ниже)
npm test           # тесты
npm run typecheck  # проверка типов
npm run build      # сборка в dist/
```

`npm run dev` ждёт `api` из корневого `compose.yaml` с `API_DEV_AUTH=true`: вне MAX у браузера нет
подписанного `initData`, и в dev-сборке фронт шлёт фейковую строку без подписи (`src/max/bridge.ts`).
Экран по `start_param` вне MAX выбирается адресом: `http://localhost:5173/?startapp=today`.

`.npmrc` включает `legacy-peer-deps`: без него npm 10 падает на дереве зависимостей Vitest
(`Cannot read properties of null (reading 'edgesOut')`).

## Что сделано

- **Экран дня** — записи выбранного дня в поясе пользователя: «весь день» первыми, потом по времени
  (порядок задаёт api); выполненные — отдельным блоком, зачёркнутыми; отменённые не показываются.
  Заголовок — «Сегодня», «Завтра», «Вчера» или день недели. Состояния загрузки, пустого дня и ошибки
  с кодом (первые 6 символов `trace_id`) и кнопкой «Повторить».
- **Другие дни** — полоска недели «Пн–Вс» с точками у дней, где есть записи; стрелки — соседние недели;
  кнопка «Сегодня» возвращает назад. Неделя грузится одним запросом, поэтому дни внутри неё
  переключаются без ожидания.
- **Обновление** — опрос раз в 20 с с `If-None-Match`: без изменений api отвечает 304 без тела.
  ETag — версия данных пользователя, а не ответа, поэтому при смене недели он сбрасывается.
  Во фоне опрос стоит, при возвращении в приложение — сразу; кто смотрел «сегодня», после полуночи
  переезжает на новый день.
- **Вход** — `POST /v1/auth/max` со строкой `WebApp.initData` как есть; на 401 клиент молча входит
  заново и повторяет запрос один раз; параллельные запросы входят один раз.
- **`start_param` (J6)** разбирается целиком: `today` открывает сегодня, `day_…` — этот день,
  `week_…` — понедельник этой недели. Карточки записи и истории ещё нет: `item_…` и `dialog`
  открывают «Сегодня», как неизвестный формат.
- **Вне MAX** production-сборка показывает «Откройте iNote в MAX».

## Структура

| Путь | Что это |
|---|---|
| `src/api/schema.d.ts` | Типы из `contracts/openapi/api.json`, генерируются: `npm run gen:api`. Руками не править |
| `src/api/types.ts` | Короткие имена типов J5: `Item`, `ItemsDay`, `Me`… |
| `src/api/client.ts` | Клиент `/v1`: токен, перевход на 401, ETag/304, ошибки → `ApiError` |
| `src/max/bridge.ts` | MAX Bridge (`window.WebApp`): `initData`, `start_param`, платформа |
| `src/navigation/startParam.ts` | `start_param` → экран (J6) |
| `src/lib/time.ts` | Даты без времени: «сегодня» в поясе пользователя, неделя, подписи дней и времени записей |
| `src/screens/day/` | Экран дня: `DayScreen`, полоска недели `WeekStrip`, ячейка записи, опрос периода (`useItemsRange`), смена дня в полночь (`useToday`) |
| `src/components/ErrorState.tsx` | Текст ошибки для пользователя по коду и код для поддержки |
| `src/mocks/` | MSW-моки J5 на примерах `contracts/examples/j5`, даты сдвинуты на сегодня |
| `src/test/` | Настройка тестов: те же моки через `msw/node` |
| `public/mockServiceWorker.js` | Воркер MSW (`npx msw init public`), нужен только `dev:mock` |

Цвета — токены MAX UI (`--background-card`, `--text-secondary`…), поэтому светлая и тёмная тема
переключаются вместе с MAX. Токены объявлены на корне `<MaxUI>`, а не на `body`: фон экрана задан
классу `.app` на этом корне.

## Договорённости с другими зонами

- **API (D)** — только чтение: в ветке D `PATCH /v1/me` убран, настройки меняются через бота;
  период `/v1/items` — не длиннее 62 дней. Записи без даты в списки за период не попадают, их видно
  только поиском. После изменения контракта у D — `npm run gen:api` и проверка типов.
- **CORS в api нет**: локально запросы идут через прокси Vite (`/v1` → `localhost:8000`), на стенде
  приложение и api должны быть на одном домене за Caddy. Другой адрес api — `VITE_API_URL`.
- **Стенд (C)**: в `deploy/docker-compose.yml` у C `max_app` пока заглушка — заменить на сборку `dist/`
  за Caddy.
- **Открыть вопрос с C**: доходит ли `payload` кнопки `open_app` до приложения как `start_param` —
  проверить на живом MAX; запасной вариант — ссылка `https://max.ru/<бот>?startapp=<start_param>`.
